# Backend, практика 1

Два задания на Python: запись клиента как объект класса и проверка рабочих часов салона. Требуется Python 3.10 или новее, сторонние библиотеки не нужны.

## Запуск

```powershell
cd backend-1-practice
python main.py
```

Результат:

```text
Список записей:
Иванова А.А. 10:00
Петрова А.А. 11:00

Количество записей после попытки с пустым именем:
0

Количество записей после попытки вне рабочих часов:
0
```

## Реализация

В `main.py` определён класс `Appoinment` с полями `id`, `client_name`, `master_id`, `service_id`, `time`. Написание имени класса сохранено из задания. `create_appointment()` возвращает объект этого класса и добавляет его в `appointments` только после всех проверок. При ошибке возвращает `None` и сохраняет список без изменений.

Проверяются непустое имя (включая строку из пробелов), целочисленные идентификаторы существующих мастера и услуги, время в формате `HH:MM`. Допустимый диапазон — **08:00–20:00 включительно**: 07:59 и 20:01 уже недопустимы. Длительность услуги в задании не указана, поэтому проверяется именно время начала записи.

Так как исходного backend в проекте не было, добавлены минимальные классы `Master`, `Service`, функции `get_master()`, `get_service()` и тестовые мастер и услуга с идентификаторами `1`. Данные хранятся в памяти и сбрасываются при перезапуске программы. Проверки пересечения записей не добавлены: в этих двух заданиях требуются заполненность полей и рабочие часы.

В примере задания `print(len(appointment))` — опечатка: считать нужно `len(appointments)`. Ожидаемый результат `0` получается, если проверять ошибочную запись на пустом списке. Поэтому каждый демонстрационный сценарий начинается с `appointments.clear()`; сама функция создания записей список не очищает.

## Тесты

```powershell
python -m unittest -v
```

Тесты проверяют создание двух объектов, незаполненные поля, неизвестные идентификаторы, границы рабочего дня, некорректное время и сохранность ранее созданных записей после ошибочного запроса.
