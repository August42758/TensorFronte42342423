# Задание 4. Асинхронный JavaScript и React

Страница выбора даты и времени «ЛУНА» из третьей практики получает данные через `fetch` от имитационного сервера. Предыдущие практики сохранены.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```powershell
cd frontend-4-practice
npm install
npm run dev
```

Откройте http://127.0.0.1:3000/ и оставьте терминал работающим. API и React обслуживает один Vite, отдельный сервер запускать не нужно. Если порт 3000 занят, остановите использующий его процесс или задайте другой порт: `npm run dev -- --port 3001`.

```powershell
npm run build
npm run preview
```

API работает и при `preview` благодаря плагину Vite. Сам по себе каталог `dist` содержит только клиент: при размещении на статическом хостинге понадобится сервер с теми же эндпоинтами.

## API и данные

- `GET /api/booking/today` → `{ day, month, year }`.
- `GET /api/slots?day=17&month=9&year=2026` → `{ date: { day, month, year }, slots: [{ time, available }] }`.
- Месяц имеет индекс 0–11. Задержка каждого ответа — 700 мс (`DELAY_MS` в `server/server.js`).
- `server/database.js` содержит серверное «сегодня» — 17 октября 2026 года — и два расписания, чередующихся по дате. Клиент не определяет сегодня по часам компьютера и не содержит расписаний.
- Занятые слоты (`available: false`) видны, но отключены. Если все слоты заняты или массив пуст, показано сообщение об отсутствии времени.
- Некорректные параметры даты дают HTTP 400, неизвестные эндпоинты — 404, неподдерживаемые методы — 405.

Прямые ссылки для проверки:

- http://127.0.0.1:3000/api/booking/today
- http://127.0.0.1:3000/api/slots?day=17&month=9&year=2026
- http://127.0.0.1:3000/api/booking/today?error=1 — пример HTTP 500.

## Архитектура

- `server/server.js` — Vite-плагин с JSON API и задержкой.
- `src/api.js` — `fetchToday()` и `fetchSlots(date)`, проверка `response.ok`, формата ответа, сетевых ошибок и тайм-аут 10 секунд.
- `src/App.jsx` — отдельные состояния данных, загрузки и ошибки для даты и слотов. Дата загружается в `useEffect`, слоты — в другом эффекте при смене выбранного дня или повторной попытке. Клик не делает второй запрос.
- При смене дня время сбрасывается, старые слоты сразу скрываются, появляется «Загрузка слотов…». «Далее» доступна только после выбора доступного времени.
- Cleanup эффекта отменяет запрос через `AbortController`; флаг активности не позволяет устаревшему запросу менять состояние. Дата ответа также сравнивается с запрошенной датой.
- В режиме разработки `StrictMode` может запускать начальный эффект повторно; первый запрос отменяется при cleanup. Это не дублирование запросов из обработчика и эффекта.
- Компоненты и оформление перенесены из третьей практики. Примеры и заготовка четвёртой практики отсутствовали, поэтому сервер, API-клиент и конфигурация созданы самостоятельно.

## Проверка трёх сценариев

1. Откройте страницу. Сначала видна «Загрузка…», затем октябрь 2026 и выбранное 17-е число. После «Загрузка слотов…» появляется расписание. Дни до 17-го отключены независимо от даты компьютера.
2. Выберите слот, затем другой день. Время сбрасывается; во время запроса старых кнопок нет. Быстро выберите несколько дней: должны появиться слоты последней даты. Стрелки листают месяцы и годы, нижняя панель показывает полный выбор.
3. Проверьте ошибки API. В PowerShell перед запуском задайте:

```powershell
$env:MOCK_API_FAIL = 'today'
npm run dev
```

Появится сообщение об ошибке даты и кнопка повторной загрузки. Значение `slots` проверяет ошибку расписания, `all` — обоих запросов. Для восстановления остановите сервер, выполните следующую команду, запустите его снова и нажмите кнопку повторной загрузки (либо обновите страницу):

```powershell
Remove-Item Env:MOCK_API_FAIL -ErrorAction SilentlyContinue
npm run dev
```

При отключении сети запрос завершится понятной ошибкой, а не бесконечной загрузкой. «Далее» показывает учебное подтверждение, запись в салон не отправляется.

## Выполненные проверки

Чистая установка через npm ci и сборка npm run build прошли успешно. В браузере проверены загрузки, выбор и сброс времени, занятые и пустые слоты, быстрые переключения дат, ошибки HTTP 500 и сети, повторные запросы, некорректная дата ответа, переход между годами и мобильная ширина. Дата календаря проверена при отличающейся дате компьютера. API проверен на форматы ответов и статусы 400, 404, 405, 500.
